# 企业知识库问答——使用说明书

> 2026-08-28 更新：正式生产环境已切换为**企业微信登录**（`AUTH_MODE=wecom`），不再是文档旧版描述的本地个人测试模式。本次更新把"真实用户怎么用"放在最前面，本地开发/测试模式的内容移到文末附录。

适用版本：云端生产部署（企业微信登录）
访问地址：<https://fineui.wwz.cool>

## 1. 系统用途

本系统把公司的制度、手册、规范等文档整理成可提问的知识库。系统会解析文档、建立中文向量索引，用大模型根据检索到的原文回答问题并显示引用来源。

## 2. 登录

不需要单独注册账号，直接用企业微信身份登录。

### 2.1 手机（企业微信内打开链接）

在企业微信的聊天/工作台里点开系统链接，会自动完成登录（静默授权），无需手动扫码或输入密码。

### 2.2 电脑（浏览器打开）

浏览器打开 <https://fineui.wwz.cool>，页面会显示一个登录二维码，用企业微信扫一扫即可登录。

### 2.3 退出登录

页面右上角身份卡片旁边有"退出"按钮，点击后会清除登录状态并重新显示二维码，可以用另一个企业微信账号重新登录（常用于测试不同权限的账号）。

## 3. 提问和查看答案

1. 打开左侧"知识问答"。
2. 右上角"知识范围"下拉框可以选择只在某个知识库内检索，也可以留空检索全部（**只会显示你有权限看到的知识库**，见第 5 节）。
3. 在底部输入问题并发送。
4. 等待系统检索并生成答案，答案会流式逐字出现。
5. 查看答案下方的引用卡片，核对文档名称、页码和原文片段。

推荐问题写法：

- "差旅报销需要哪些材料？"
- "采购金额超过五万元由谁审批？"
- "请根据资料列出年假申请流程。"
- "这份制度中关于信息安全有哪些禁止事项？"

如果问题没有资料依据，系统会提示上下文不足。重要信息应以引用原文为准，不要只依赖生成的回答文字；系统偶尔会把大模型自己的通用回答标注为"非企业官方文档内容"，这类回答仅供参考。

## 4. 权限与可见范围

系统按**企业微信部门**做访问隔离，登录后你能看到的内容由所在部门决定：

- 一份文档如果设置了"访问组"（比如只对某个部门开放），只有该部门的人能检索到，其他人问同样的问题也不会召回这份文档，界面上也看不出它的存在。
- 一份文档如果没有设置访问组，租户内所有人都能看到。
- "所属部门"字段只是描述性标签（用于标注这份文档是哪个部门发的、显示在引用里），**不影响谁能看到**——真正决定可见性的是"访问组"。
- "知识范围"下拉框（第 3 节）里列出的知识库，也是按你能不能看到里面的文档来过滤的：一个知识库如果全部文档都对你的部门关闭，这个知识库本身也不会出现在下拉框里。

普通员工看到的导航栏只有"知识问答"一项；"文档管理""角色权限"两个入口只有拥有对应权限的管理员账号才会显示。

## 5. 文档管理（管理员）

拥有 `document.manage` 权限（或 super_admin）的账号，左侧导航会出现"文档管理"。

### 5.1 新建逻辑知识库

在"文档管理"页面顶部的"组织你的知识空间"区域填写知识库名称，点击"新建"。不建也可以，文档会进入默认范围；有多个部门/主题时建几个能让检索更准确。已有知识库可以点名称直接改名。

### 5.2 上传资料

1. 在"添加资料"区域选择或拖入文档，支持批量多选。
2. 支持 PDF、DOCX、PPTX、图片（PNG/JPG/JPEG）、Markdown、TXT，单个文件最大 30 MB。批量上传时统一使用各自文件名作为标题。
3. **所属部门**：从企业微信部门下拉列表中选一个，作为描述性标签（不影响访问权限，见第 4 节）。
4. **按部门隔离**：勾选式部门树（支持展开/收起），勾选后只有对应部门的人能检索到这份文档；不勾选任何部门表示不按部门限制。
5. **自定义访问组**：可以额外填自定义组名（比如 `vip`），跟部门勾选叠加使用；两者都不填 = 租户内所有人可见。
6. **所属知识库**：勾选框列表，可多选；不选则进入默认范围。
7. 点击"上传并建立索引"，等待资料列表中状态变为 `ready`。

### 5.3 修改已上传文档

资料列表每一行有"编辑"按钮，可以修改所属部门、按部门隔离的勾选、自定义访问组、所属知识库，不需要重新上传。"更新版本"按钮用于替换文档内容（保留同一份文档的历史版本），不要用"添加资料"重新上传同一份文件，否则会变成两份互相独立的文档。

### 5.4 删除文档

点"删除"，确认后会删除文档记录、片段和对应向量索引。删除是实质性操作，需要保留的资料应先备份。

## 6. 角色与权限管理（管理员）

拥有 `role.manage` 权限（或 super_admin）的账号，左侧导航会出现"角色权限"。

- **新建角色**：仅超级管理员可以创建自定义角色，可勾选该角色拥有的权限码。
- **给账号分配角色**：填企业微信 userid（通讯录里的"帐号"字段），选择角色后分配，该账号下次登录即生效。`super_admin` 不能在这个页面分配，只能通过服务器配置授予（防止越权自我提权）。
- 页面下方"系统权限一览"列出全部权限码及其作用范围，角色本质上就是这些权限码的集合。

## 7. 常见问题

### 打不开登录二维码 / 手机进不去

- 确认是在企业微信 App 内打开的链接，不是外部浏览器。
- 企业微信内置浏览器有时会缓存旧页面：完全关掉这个聊天里打开的页面（不是简单下拉刷新），重新点链接进入。

### 明明文档已经上传，问答却查不到

- 确认文档状态是 `ready`（未完成索引前查不到）。
- 检查上传时设置的部门/访问组是否包含你自己的部门——如果被限制在其他部门，你本来就看不到，这是设计行为，不是 bug。
- 换用更具体、接近原文表达的问题。

### 回答没有引用或提示"资料不足"

- 确认文档状态为 `ready`。
- 检查提问时是否选错了"知识范围"。
- 检查资料本身是否确实包含答案。

### 批量上传后感觉页面卡住/像是崩了

服务器同时只能处理 2 个文件的索引任务（受硬件规模限制），一次传几十个文件会排队处理，不是崩溃。建议大批量资料分批、少量多次上传，方便发现单个文件失败时能快速定位。

## 附录：本地开发 / 测试环境（非生产使用方式）

以下内容适用于**在自己电脑上跑一份完整的本机 Docker 技术栈做开发或个人测试**，跟上面描述的云端生产环境（企业微信登录）是两回事——本地默认使用 `AUTH_MODE=dev` 固定身份，没有企业微信登录、没有真实部门权限隔离。

访问地址：<http://localhost:8000>

当前主要组件：

- FastAPI：网页和问答接口
- PostgreSQL/pgvector：文档信息和向量数据
- Redis/Celery：后台文档处理
- FastEmbed/BGE：本地中文向量化
- DeepSeek：生成最终回答
- ClamAV：上传文件病毒扫描（可选，`CLAMAV_HOST` 留空则跳过）
- Tesseract：扫描图片和扫描 PDF 的中文 OCR

### A.1 每次使用前如何启动

从 Windows 开始菜单打开 Docker Desktop，等待其显示正在运行。打开 PowerShell，执行：

```powershell
Set-Location C:\Users\w\Desktop\enterprise-rag-docker
docker compose up -d
docker compose ps
```

当 PostgreSQL、Redis、API 和 Worker 均显示 `healthy` 时，说明启动成功（`clamav`、`reranker` 走 profile 按需启动，默认不带这两个也能正常问答）。

本机使用英文目录联接（`C:\Users\w\Desktop\enterprise-rag-docker`）是为了避免 Docker BuildKit 无法稳定处理中文构建路径。它指向原项目，不是另一份副本。

浏览器访问：

- 使用页面：<http://localhost:8000>
- API 文档：<http://localhost:8000/docs>
- 健康检查：<http://localhost:8000/api/health>

页面左下角显示"服务运行正常"和"pgvector · 模型已连接"即可开始使用。

### A.2 上传资料（本地模式）

本地 `AUTH_MODE=dev` 下没有企业微信部门树，上传表单的"所属部门""按部门隔离"这两个字段会因为读不到企业微信部门列表而显示为空——这是正常现象，不影响其他功能。个人测试时"自定义访问组"可以留空，代表当前租户内可见。

其余上传步骤、支持的文件类型、文档整理建议与云端生产环境（第 5.2 节）一致。

### A.3 日常停止和重新启动

```powershell
Set-Location C:\Users\w\Desktop\enterprise-rag-docker
docker compose stop     # 停止服务但保留容器和数据
docker compose start    # 重新启动
docker compose down     # 完整停止并移除容器（不删数据库/上传文件/模型缓存卷）
```

普通情况下不要执行 `docker compose down -v`。其中 `-v` 会删除 PostgreSQL、上传文件和模型缓存卷，可能造成数据丢失。

### A.4 修改配置后重新应用

修改 `.env` 后执行：

```powershell
Set-Location C:\Users\w\Desktop\enterprise-rag-docker
docker compose up -d --force-recreate api worker
```

然后打开 <http://localhost:8000/api/health>，确认 `model_ready` 为 `true`。仅刷新浏览器不会让容器重新读取环境变量。

### A.5 代码更新后的推荐流程

```powershell
Set-Location C:\Users\w\Desktop\enterprise-rag-docker
docker compose --progress plain build api worker
docker compose up -d --no-build api worker
docker compose ps
curl.exe http://127.0.0.1:8000/api/health
```

该流程只更新 API 和 worker，PostgreSQL、Redis 以及数据卷保持不变。检查数据库迁移是否已到最新版本：

```powershell
docker compose exec -T api alembic current
```

若构建时网络下载超时：项目已经为 pip 配置了下载缓存、120 秒超时和自动重试，可直接重新执行同一条 `build` 命令，已下载的依赖会被复用。

### A.6 备份与恢复演练

创建备份：

```powershell
Set-Location C:\Users\w\Desktop\enterprise-rag-docker
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\backup.ps1
```

脚本会在 `backups` 目录生成 PostgreSQL SQL 备份、上传文件备份目录，以及包含文件大小和 SHA-256 的校验清单；还会在 Windows 上收紧备份目录权限，仅保留当前用户、系统和管理员访问。备份中含原始文档和数据库内容，不要发送给无关人员。建议在大量新增或删除资料前执行一次备份。

安全的恢复演练（把时间部分替换成实际备份名称，只创建临时数据库比对内容指纹，不覆盖当前数据，结束后自动清理）：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass `
  -File .\scripts\restore-drill.ps1 `
  -DatabaseBackup .\backups\rag-时间.sql `
  -UploadsBackup .\backups\uploads-时间 `
  -OutputReport .\reports\restore-drill.json
```

`restore.ps1 -ConfirmRestore` 会覆盖当前数据库对象，个人日常测试不要随意运行。

### A.7 修改模型密钥

密钥保存在项目根目录的 `.env` 文件中。不要把密钥发送到聊天、截图、邮件或提交到代码仓库。修改后按 A.4 重新创建容器。

本地 BGE 用于生成文档向量；回答阶段会把检索出的相关片段发送给配置的聊天模型（如 DeepSeek）。对高度敏感资料，应先确认是否允许发送给外部模型服务。

### A.8 常见问题（本地模式）

**页面打不开**：确认 Docker Desktop 已启动 → `docker compose up -d` → `docker compose ps` 查看是否全部 `healthy`。

**页面显示"无法连接服务"**：`docker compose logs --tail 100 api`，重点查看数据库连接、模型密钥或端口占用错误。

**文档一直停留在处理中**：`docker compose logs --tail 100 worker`；首次使用中文 BGE 模型时需要下载模型，请等待。

**上传失败**：常见原因包括文件超过 30 MB、格式不支持、扩展名与实际内容不一致、文件内容已存在、Office 文件损坏、ClamAV 检测到风险内容（若启用）。

**修改 `.env` 后没有生效**：执行 `docker compose up -d --force-recreate api worker`，仅刷新浏览器不会让容器重新读取环境变量。

### A.9 查看运行状态和日志

```powershell
docker compose ps                          # 所有服务状态
docker compose logs --tail 100 api         # API 日志
docker compose logs --tail 100 worker      # 后台入库日志
docker compose logs -f                     # 全部服务实时日志（Ctrl+C 退出不会停止服务）
```

### A.10 个人测试推荐配置

- `AUTH_MODE=dev`
- Docker 单机 PostgreSQL/pgvector
- 本地 BGE 中文嵌入
- DeepSeek 聊天模型
- Redis/Celery 后台入库

暂时不需要配置企业微信/OIDC 接入、数据库高可用、负载均衡、正式峰值压测、外部渗透测试或企业级备份策略。

### A.11 快速检查清单

1. Docker Desktop 正在运行。
2. `docker compose ps` 中核心服务均为 `healthy`。
3. 页面左下角显示服务正常、模型已连接。
4. 文档上传后状态变为 `ready`。
5. 回答带有正确引用。
6. 定期运行备份脚本。

### A.12 管理维护接口

个人测试一般不需要手动调用维护接口。遇到数据库提交失败、异常停机或怀疑向量数量不一致时，可在 API 文档中执行 `POST /api/admin/vector-index/reconcile`。返回的 `added` 和 `deleted` 表示本次修复的缺失向量与孤儿向量数量；正常状态通常都为 0。

知识库支持停用、重新启用和删除。已关联文档的知识库不能直接删除，应先调整文档归属；停用后普通问答不会再自动路由到该知识库。
