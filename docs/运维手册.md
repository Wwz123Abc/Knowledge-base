# 生产运维手册

## 发布

1. 构建带不可变版本号的镜像。
2. 在预发布环境执行 `alembic upgrade head`、自动化测试和离线评测（`python -m evals.run_eval --dataset mechanical`，另有一套 `sample` 启动评测集，见 `evals/README.md`）。
3. 先将 5% 流量切换到新版本，观察错误率、P95 延迟、检索召回、Token 成本和用户负反馈。
4. 指标稳定后逐步扩容；异常时把流量切回上一镜像。数据库迁移必须保持向后兼容，禁止依赖自动降级。

## 监控

Prometheus 指标位于 `/api/metrics`。以下为完整清单；**300 人部署按 `docs/优化与容量.md` 第四节只盯 4 个即可**（5xx、429、流式中断率、问答延迟）。至少告警：

- 5xx 比例超过 1%
- P95 问答延迟超过业务阈值
- 入库失败或积压持续增加
- 模型调用错误、Token 或费用突增
- PostgreSQL 连接池耗尽、磁盘不足、复制延迟
- Redis 不可用或缓存命中率异常

`GET /api/health` 返回 `database`、`redis`、`clamav`、`model` 和 `details`。已配置依赖探测失败时总状态为 `degraded`；未启用的 Redis/ClamAV 显示 `disabled`。模型轻量探活默认关闭，生产可设置 `HEALTH_CHECK_MODEL=true`，并通过 `HEALTH_DEPENDENCY_TIMEOUT_SECONDS` 限制每项探测时间。

受控 SQL 工具通过 `TOOL_SQL_TIMEOUT_MS` 设置事务级执行超时；PostgreSQL 使用本地事务 `statement_timeout`，不会污染连接池中的后续请求。

检索明细、原问题/改写问题、片段得分、回答耗时和 Token 使用保存在 `retrieval_traces`；管理员操作记录在 `audit_logs`。

## 数据库与恢复

- 生产使用托管 PostgreSQL 高可用或一主多备架构，不使用单节点 Compose 数据库。
- 开启持续归档和时间点恢复，至少每日全量备份。
- 上传文件和数据库必须使用同一恢复点或保留可重建索引的版本映射。
- 每季度在隔离环境执行恢复演练并记录 RPO/RTO。

本地演练可以运行：

```powershell
.\scripts\backup.ps1
.\scripts\restore-drill.ps1 `
  -DatabaseBackup .\backups\rag-时间.sql `
  -UploadsBackup .\backups\uploads-时间 `
  -OutputReport .\reports\restore-drill.json
```

`restore-drill.ps1` 创建独立临时数据库，比较文档、片段、检索追踪和向量表的内容指纹，然后自动清理临时库，不覆盖在线数据库。只有确实需要覆盖当前数据库时才使用 `restore.ps1 -ConfirmRestore`，执行前必须再次确认备份、目标环境和停机窗口。

## 容量

**300 人内部部署**（当前目标规模）：按 `docs/优化与容量.md` 第四节执行即可——只有限流口径（R1）一项配置调整 + 3 步上线检查，可选 20 虚拟用户轻量压测（30 分钟内），监控盯 4 个指标就够。

明确要扩容到超过 300 人规模后，再使用 `tests/load/k6-chat.js` 执行正式压力测试。可通过 `PEAK_VUS`、`RAMP_UP`、`HOLD`、`RAMP_DOWN` 和 `P95_LIMIT_MS` 调整场景，并按真实文档量、并发、模型延迟重新设定阈值。API 与 Celery worker 可独立扩容；pgvector、Redis 和模型服务需要单独容量规划。

## 索引一致性与扩容

- 词法检索由数据库执行：PostgreSQL 使用 `pg_trgm` GIN 索引，SQLite 使用 FTS5，不再按请求把全部片段载入 Python 内存。
- 管理员可以调用 `POST /api/admin/vector-index/reconcile` 对账。接口会幂等补齐缺失向量并清理孤儿向量，建议在异常恢复和定期维护窗口执行。
- 文档标题、部门等纯元数据修改会直接更新向量元数据，不再重建整篇文档；ACL 或知识库归属变化仍会排队重建。
- 限流和问答取消状态默认存入 Redis，多 API 实例共享；Redis 短暂不可用时会降级为进程内状态。
- 只有直连地址出现在 `TRUSTED_PROXY_IPS` 中时才接受 `X-Forwarded-For`。生产反向代理上线前必须填写实际代理地址，不能使用任意网段。

## 备份访问控制

`backup.ps1` 在 Windows 上默认关闭 `backups` 目录的继承权限，只保留当前用户、SYSTEM 和本机管理员的完全控制，并在清单中记录权限与加密提示。若目标存储已有经过审核的 ACL，可显式使用 `-KeepInheritedPermissions`。访问控制不等于静态加密，正式备份仍应存放在 BitLocker、EFS 或企业加密备份介质上。
