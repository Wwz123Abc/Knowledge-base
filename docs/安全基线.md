# 安全基线

## 已实施

- 企业微信登录（生产）/ OIDC/JWT 服务端身份认证和角色控制，前端提交的身份字段不参与鉴权
- 细粒度 RBAC：角色-权限码体系（`role.manage` / `system.admin` 等）；`super_admin` 仅能由服务器配置授予（`WECOM_SUPER_ADMIN_USERIDS`），角色分配页面不可授予，防止越权自我提权
- 租户隔离、多访问组检索前过滤
- 文档扩展名、文件签名、DOCX 结构、大小和压缩炸弹检查
- ClamAV 流式病毒扫描，容器模式采用失败关闭策略
- 提示注入检测和提示词隔离
- 审计记录个人信息脱敏
- 只读 SQL AST 校验、表白名单和结果行数限制
- HTTP 工具域名白名单、DNS 公网地址检查、禁止重定向和响应大小限制
- 工具执行前人工审批及持久化结果
- 请求限流、安全响应头、CORS 白名单和请求 ID
- 容器使用非 root 用户

## 失败关闭与代理边界

- `TOOL_ALLOWED_TABLES` 为空时，`sql.read` 拒绝所有查询；只有显式列出的表可读，数据库账号本身仍必须是只读账号。
- `http.get` 默认只允许 HTTPS，并继续执行域名白名单、DNS 公网地址、禁止重定向和响应大小检查。仅在隔离开发环境确有需要时设置 `TOOL_HTTP_REQUIRE_HTTPS=false`。
- 空字符串环境变量不会再静默回落到 `.env`。例如显式传入空的模型密钥会使模型处于未就绪状态，避免误用磁盘中的真实密钥。
- `X-Forwarded-For` 仅对 `TRUSTED_PROXY_IPS` 中的直连代理生效；不要为了方便信任全部来源。
- 请求 ID 通过上下文自动写入审计表，可用于关联网关、API JSON 日志与管理操作。
- 提示注入检测是两层防线：规则层先做 Unicode 规范化，识别常见中英文越权、角色替换和指令泄漏变体；规则命中或高可疑时，再由 LLM 复核层二次判定（`app/core/rag.py` `_is_prompt_injection`），在降低漏判的同时控制误杀，命中后写入审计日志。它仍是纵深防御的一层，不能代替 ACL、来源隔离和人工审查。

## 部署要求

- 所有外部流量通过 TLS 终止的反向代理或网关。
- 数据库工具账号必须由数据库自身授予只读权限，代码校验不是权限替代品。
- 模型密钥、数据库密码、企业微信 Secret/Session 签名密钥和 OIDC 配置通过密钥管理系统注入，不写入镜像或仓库。
- 上传目录、数据库备份和日志应加密并设置保留周期。
- ClamAV 失效时采用失败关闭策略；高安全环境不应留空 `CLAMAV_HOST`。
- 每次发布运行依赖漏洞扫描、权限回归、提示注入用例和恢复演练。

本地 Docker 验收已使用标准阳性测试样本验证扫描链路，API 返回 HTTP 400 且未创建文档。`pip-audit` 最终扫描 140 个依赖，未发现已知漏洞。
